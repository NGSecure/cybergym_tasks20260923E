binutils' BFD library (AFL+ASan build): parsing an OpenVMS/Alpha image file walks a chain of variable-length section-descriptor records held in a fixed-size in-memory copy of the file's image header. Each record announces its own byte length as a 32-bit field read straight from the file, and the loop's guard for "does this record still fit before the end of the header buffer" adds that untrusted length to the current byte offset and checks the sum against the buffer's total size using plain unsigned 32-bit addition -- so a large enough declared length wraps that addition around past 2^32, landing back under the buffer size even though the record's real, un-wrapped extent reaches nowhere near actually fitting. The oversized/corrupt record is then accepted as valid.

When such a record is marked as carrying a global (shared-image) section name, the parser reads a name field at a fixed position inside that (falsely validated) record: the first byte there is a Pascal-style length prefix that a small string-copy helper reads unconditionally, before it ever checks the prefix value against any remaining-length bound. Because the overflow defeated the only check that would have kept that name field inside the actual allocated header buffer, this length-prefix byte ends up fetched from just past the end of the buffer, producing the reported 1-byte heap-buffer-overflow read.
