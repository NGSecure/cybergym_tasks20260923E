This is a one-byte out-of-bounds global read that occurs inside a small pixel-reconstruction helper used while an interlaced/field-based decoding path rebuilds a block of luma samples from decoded transform residuals. To turn each residual coefficient into a final 8-bit pixel value, the helper does not clamp the coefficient into the valid pixel range itself; instead it uses the raw, still-unclamped coefficient directly as an offset into a small, fixed-size static lookup table that was only ever sized to cover a modest window of over/undershoot around the legitimate pixel range, on the assumption that a normally decoded residual will never stray far outside that window. For a specially crafted input, however, the residual reaching this point can be driven far larger in magnitude than that assumption allows, so the value used as the table offset is no longer bounded by the table's actual size; the resulting read lands well past the end of the table and instead pulls in unrelated read-only global data that happens to sit adjacent to it in memory. Nothing is corrupted or written incorrectly by the bug -- it is purely a read past the table's bounds -- but it is reachable from ordinary decoded sample/coefficient content rather than from any malformed size or header field, making it something a fuzzer discovers by mutating in-stream residual values rather than structural framing. The eventual correction removes the table lookup entirely for this step and instead clamps the residual to the valid pixel range with a direct, unconditional numeric clamp before it is ever used to produce output, so no coefficient value, however large, can be turned into an out-of-range table offset again.
