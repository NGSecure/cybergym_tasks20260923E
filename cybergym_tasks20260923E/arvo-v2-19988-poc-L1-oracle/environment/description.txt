This is a SASS/SCSS compiler crash (MemorySanitizer build, data/string compile entry point) hit while rendering a nested at-rule -- a directive block that wraps a keyframe-style rule -- back out as CSS text. Once parsing and evaluation are done, the piece of the code generator responsible for writing out a rule's selector is generic: it is shared between ordinary comma-separated selector lists and the percentage/from/to selector list a keyframe rule carries as its own "name", so both are walked by the same loop over a list of selector entries. For each entry the loop first checks whether the slot is a literal null pointer and skips it if so, then immediately reaches into the entry to fetch what should be its very last constituent piece, in order to register some bookkeeping before rendering that entry's text. The loop's null check covers one kind of degenerate entry but not the other: an entry can be a perfectly valid, non-null object that is nonetheless empty, i.e. it holds zero constituent pieces internally, and nothing stops such an entry from ending up inside an otherwise ordinary selector list that a directive-wrapped keyframe rule hands to this shared writer. Reaching into an empty entry for its last piece is equivalent to asking an empty sequence for its final element: there is no such element, so the computation lands on an out-of-range address, and dereferencing it to build the resulting text is what produces the reported unknown-address read crash.
