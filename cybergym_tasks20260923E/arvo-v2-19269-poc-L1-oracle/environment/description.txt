This is a heap out-of-bounds read in nDPI's TLS certificate-detection logic, triggered while it walks the list of extensions attached to a captured TLS handshake message looking for the extension that carries the requested server name. Once that extension is found, the code reads a 16-bit length field describing how many bytes of extension data follow, clamps that length only against the capacity of a local scratch buffer used to hold a null-terminated copy of the value, and then copies that many bytes starting at the extension's data offset inside the packet's payload into the scratch buffer. Nothing checks, before the copy runs, whether the extension's data offset plus its declared length still lies within the bytes actually captured in the packet's payload allocation — only the destination buffer's size is considered, never how much of the source packet genuinely remains. A crafted handshake message that advertises an extension length larger than what is actually present after its data offset causes the copy to walk past the end of the heap buffer backing the packet payload, and that read past the allocation's end is what triggers the crash.
