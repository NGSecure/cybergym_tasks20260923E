The defect lives in a camera-identification code path that, once it recognizes a raw-image file as coming from a specific camera model, looks up that model's built-in color-correction data and copies twelve individual coefficient values out of a matching table entry into a matrix meant to be organized as four rows of three coefficients each. The copy is driven by a single running counter that advances from the first coefficient straight through the twelfth, but each individual write still addresses the destination through a reference to only the first row's three-slot sub-array rather than recomputing which row and column the counter has actually reached; so the first three coefficients land correctly, and for every one of the remaining nine coefficients the same three-slot reference is reused with a counter value that has already run past that sub-array's own declared bound. Because the four rows happen to be laid out one after another in memory, those later writes still end up inside the overall matrix object rather than corrupting anything beyond it, but each is performed through an array reference whose declared size is smaller than the index used against it, which is undefined behavior that a bounds-aware sanitizer build flags on every one of the nine affected writes. The same mis-indexed copy pattern is duplicated across two adjacent branches of the routine — one taken when the matrix is only recorded for internal bookkeeping, and a second, functionally identical one taken when the values are also mirrored into a second buffer for external use — so any input that drives the model lookup to this particular table entry triggers the fault deterministically, independent of any size an attacker could otherwise grow or shrink to slip past a guard.
