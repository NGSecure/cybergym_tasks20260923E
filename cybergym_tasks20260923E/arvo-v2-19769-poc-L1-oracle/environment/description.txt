ImageMagick's LABEL coder expands label metadata containing the FX image-calculator expression syntax through the same property-text-expansion path used elsewhere in the library; a fuzz harness that constructs an image directly from label-format bytes via ImageMagick's C++ read API triggers a heap-buffer-underflow (AddressSanitizer reports it as a 1-byte WRITE) while the FX expression evaluator parses that text. Root cause: the evaluator recognizes several built-in keyword-style pseudo-functions -- an identifier immediately followed by an opening parenthesis and argument text -- by checking only that the character right after the matched keyword name is either whitespace or an opening parenthesis; that check also silently accepts the case where the keyword is the very last thing in the expression, since the string's terminating NUL trivially satisfies "not whitespace". An expression whose entire text is exactly one of these bare keyword names -- with no parenthesis and no argument text at all -- is therefore misclassified as a genuine invocation of that keyword. The evaluator then copies the (nonexistent) argument text expected to start right after the keyword into a scratch buffer; the copy naturally produces zero bytes, and the code unconditionally writes a NUL terminator at the copied text's "last byte" position without checking for that zero-length case first -- the position arithmetic underflows and the write lands one byte before the start of the scratch buffer.
