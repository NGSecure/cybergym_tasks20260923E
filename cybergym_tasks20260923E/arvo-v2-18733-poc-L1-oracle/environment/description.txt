This is a two-byte heap-buffer-overflow read landing just past the end of a small dynamically allocated packet buffer, triggered while the TLS classifier is inspecting a handshake-looking flow that has not yet been confirmed to carry a certificate record. Before treating a slice of the payload as a 16-bit big-endian length value, the code guards the access with a size comparison against a fixed offset into the buffer, but that comparison only guarantees that one more byte exists at the offset rather than the two contiguous bytes the subsequent read actually consumes to build the 16-bit value. Because of this off-by-one in the bound rather than a missing check altogether, a payload whose length is exactly one byte short of what a two-byte read at that offset would require still passes the guard, and the code proceeds to dereference both bytes, walking a single byte beyond the allocation's end. The overrun is minimal — one byte past a roughly one-hundred-byte buffer, not a large runaway read — which is the signature of a strict-vs-inclusive comparison-operator mistake rather than an absent length check. The vulnerable comparison is only reached on connections not already recognized as carrying a TLS certificate, so a crafted flow only needs to present a payload length sitting exactly on this boundary value, growing the region the code is willing to scan by one byte beyond what was actually validated, to make the parser read out of bounds.
