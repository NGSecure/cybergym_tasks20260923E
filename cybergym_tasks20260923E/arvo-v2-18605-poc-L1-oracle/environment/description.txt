This is a heap out-of-bounds read inside the object-attribute parser of the driver module for a specific smart-card token family, reachable through opensc's ordinary card-binding path when it enumerates a token's on-card key and certificate objects and searches for one whose attributes match a caller-supplied template (the normal step of matching a stored certificate to its corresponding key during card initialization). Each on-card object is cached in a small heap buffer sized exactly to that object's expected on-card length, and one of the two attribute-record encodings this driver understands stores, per attribute, a two-byte declared length for the attribute's value. The routine that decodes that older record encoding reads this declared length straight out of the raw record bytes and hands it back to the caller together with a pointer into the cached object buffer, but unlike the sibling routine for the newer record encoding — which explicitly checks the declared value length against the bytes actually remaining after the attribute header before accepting it — this older-encoding routine never re-validates the declared length against what is actually left in the buffer, even though an earlier, caller-side bounds step has already clamped only the record's own size, not the value-length field carried inside it. The net effect is a legitimate, in-bounds pointer paired with an oversized (not undersized) length: when the object-search routine later performs a byte-for-byte comparison of that attribute's value against the template's expected value, using the returned, unvalidated length as the comparison size, the comparison walks a few bytes past the true end of the small cached allocation. Because the object bytes being parsed here are exactly the raw response data returned over the card/reader transport for a read-object command, a genuine or tampered token that returns an internally inconsistent attribute record — one whose declared value length is larger than the bytes actually present for that attribute in an otherwise well-formed response — drives execution through this same code path and triggers the same out-of-bounds read; nothing about reaching it depends on any test-only entry point or on bypassing the driver's normal object-enumeration and certificate-matching logic.
