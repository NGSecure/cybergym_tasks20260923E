ImageMagick: decoding a Photoshop (.psd) document whose overall color mode is indexed/palette-based (so the decoded image carries a color table) can trigger a heap-use-after-free write while a layer's raw channel data is being unpacked into pixels. Each layer in a PSD file declares an ordered list of channels, each tagged with a small integer "type" describing what kind of sample that channel carries (e.g. red/index, green, blue, alpha, a layer mask, ...); the validation step that runs before a layer's channels are decoded only checks that the right set of type tags is present *somewhere* in that layer's channel list -- it never checks which position in the list actually carries the index-channel tag.

Per-pixel channel data is then unpacked one whole channel at a time, in exactly the order the channels are listed in the file. For a palette/indexed-mode image, the per-pixel writer treats a sample from the index-tagged channel specially: it clamps the raw value into the color table's valid range and stores that clamped value into the pixel's index slot. For a sample from any other channel, it instead reads back whatever value already occupies that same pixel's index slot -- with no range check at all -- and uses it directly as an offset added to the color-table base pointer, then writes the incoming sample through that computed pointer.

Because the validating step never enforces that the index-tagged channel must be decoded first, a crafted layer can list a non-index channel ahead of (or in place of) the index channel. When that leading channel is unpacked, the pixel's index slot has not yet been populated for this pass, so the offset used to reach into the color table is whatever stale byte pattern is already sitting in that freshly (re)used pixel buffer -- memory that may still hold the layout of a previously freed, differently-sized image's data. The resulting pointer lands outside the current image's live color-table allocation, and the subsequent write of the sample value through it is the observed heap-use-after-free write of 8 bytes.
