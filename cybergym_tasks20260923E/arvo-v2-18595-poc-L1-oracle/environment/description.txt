This is a heap-use-after-free read inside libavc's Android H.264 decoder, specifically a stale-pointer bug rather than an out-of-bounds overflow: a SIMD-accelerated sub-pixel luma interpolation routine used during motion-compensated inter prediction issues a fixed-size 16-byte read from a reference-picture block, and the pointer it reads through refers into a roughly 588KB frame buffer that had already been released back to the allocator well before this read happened, with the touched offset sitting comfortably in the interior of that freed region rather than at either edge, which rules out a simple bounds-check slip and points instead to a lifetime/ownership problem. The freeing side is triggered by a mid-stream decoder reset that tears down and (later) reallocates the dynamic per-stream buffers, including the reference-picture bookkeeping table the decoder consults to locate each reference frame's pixel data; the bug is that, at the moment those buffers are released as part of the reset, the raw per-entry buffer pointers inside that bookkeeping table are left holding their old values instead of being invalidated right then, and only get overwritten with fresh, valid addresses later, during the next full buffer (re)allocation pass. Because nothing else marks those entries as invalid in between, any inter-slice parse and motion-compensation pass that runs against the decoder state before that next allocation completes finds an apparently normal, non-null reference pointer in the bookkeeping table and dereferences it as if it still pointed at live picture data, when in fact it points into memory the allocator is now free to reuse -- the read succeeds mechanically (ASan flags it because the region is poisoned as freed) rather than crashing outright, which is exactly the read/write-after-free hazard class. The fix restores correct temporal ordering by moving the invalidation of those same reference-buffer pointers so it runs immediately alongside the buffer-teardown step of the reset path itself, closing the window during which a reset-in-progress decoder state can still be walked and its dangling reference pointers dereferenced by a subsequent inter-predicted slice's reconstruction.
