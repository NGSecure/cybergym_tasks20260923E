ImageMagick's WebP decoder (ASan build, heap-buffer-overflow read of 3 bytes) crashes while a helper routine inspects a container-level extended-header block to decide whether an incoming WebP image is lossless: it walks a sequence of sub-chunks, reading each sub-chunk's declared payload size straight from the file and using it, unsigned and unchecked, both to compute how far to advance a running byte offset and to re-evaluate the loop's own continuation test. A crafted, truncated WebP blob supplies a sub-chunk size large enough that adding it to the current offset wraps the (32-bit) unsigned arithmetic around; the loop's continuation test performs the same kind of addition on the wrapped offset rather than bounding the offset itself against a fixed limit, so it spuriously still reports "in range" and the loop runs one more iteration with an offset that has effectively become negative. That wrapped offset is then used to compare a few bytes of the input against a known chunk-tag constant, causing the read to land a couple of bytes before the start of the allocated input buffer.
