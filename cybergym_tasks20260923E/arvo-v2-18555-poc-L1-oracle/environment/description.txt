A routine that walks a serialized, attacker-controlled buffer to confirm it is well-formed keeps a running countdown of how many bytes of the buffer have actually been certified as present, decrementing it once per loop iteration as it steps over each variable-length record packed inside. On each iteration the loop first computes a pointer to where the next record's small fixed-size header should sit and immediately reads two fields out of it -- a type tag and a claimed payload length -- before it ever checks whether the countdown is even large enough to still contain a whole header. When an earlier iteration leaves the countdown positive but smaller than one full header, the loop nonetheless enters and dereferences those header fields first, so the tag and length values it bases its accept/reject decision on come from bytes lying past the region the countdown had verified as belonging to the buffer's declared content; those trailing bytes were never written by the untrusted input and hold whatever leftover, indeterminate content the underlying allocation happened to contain. The tag value is then compared against a fixed record kind to decide whether the length must equal a specific expected size, and that comparison result -- along with the too-small check that only runs afterward -- determines whether the whole structure is rejected, so a deliberately truncated buffer that leaves a short, sub-header remainder right before the end can make acceptance hinge on uninitialized data flowing through a read rather than being caught by a bounds check up front. The corrected version reorders the loop body so the countdown-versus-header-size check runs strictly before the header pointer is dereferenced at all, and further delays using the header's reported length until enough remaining budget has also been confirmed for that length itself, ensuring every field read is preceded by a check that the bytes it reads from were actually within the verified-present region.
