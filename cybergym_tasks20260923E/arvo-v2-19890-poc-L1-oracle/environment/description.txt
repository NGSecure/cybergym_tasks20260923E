Open vSwitch's datapath flow-key/action fuzz target (MemorySanitizer build) round-trips a textual ODP action string through the Netlink-attribute encoder and back: it parses the text into a nested Netlink attribute (e.g. a tunnel key holding many repeated sub-fields), then re-formats that encoded buffer back to text. Root cause: the routine that closes off a nested Netlink attribute writes the attribute's total accumulated byte count straight into its fixed 16-bit length field with no check that the count actually fits, so when the parser is fed input that keeps appending sub-attributes into the same nested container until the underlying buffer's realloc growth pushes the nested content past what a 16-bit length can represent, the stored length silently wraps to a small, wrong value that no longer reflects how much was really written. When the formatter later walks that nested attribute, it trusts this corrupted (too-small) length as the boundary and, while validating a subsequent attribute header inside it, reads past the region that was ever actually filled in with real payload and into freshly grown buffer space that was never initialized, which MemorySanitizer reports as a use-of-uninitialized-value inside the length/bounds check.
