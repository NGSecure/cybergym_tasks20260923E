YARA's bison-generated rule-string parser (UBSan build under the rules-string fuzz harness) trips an out-of-bounds array index while reducing a deeply nested "for ... in ... : ( ... )" loop expression: entering a new loop first checks whether the compiler's fixed-size per-loop bookkeeping array is already full and, if so, records a nesting-limit-exceeded error, but the very next two statements in that same grammar action unconditionally index into that array at the current (already-at-capacity) slot to initialize per-loop counters before the recorded error is ever checked, so a rule string that nests one more "for" loop than the array has slots for drives the index one past the array's last valid element.
