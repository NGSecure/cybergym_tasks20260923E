FFmpeg's AV1 coded-bitstream frame-header parser (UBSan build, reached through the demuxer's frame-header probing path) triggers an out-of-bounds array read at index -1 while computing the pair of reference frames eligible for AV1's skip-mode inter-prediction shortcut on an inter frame header. Root cause: earlier in the same uncompressed-header parse, when the bitstream signals its seven per-frame reference-frame slots using AV1's compact short-form (only the "last" and "golden" slots are coded explicitly), the parser skips the spec-mandated derivation step that is supposed to back-fill the remaining five slots with concrete indices into the eight-entry decoded-reference-frame-state table by comparing each candidate reference's order hint against the current frame's; those slots are simply left holding an unresolved placeholder instead of a real index. The skip-mode setup logic that runs immediately afterward loops over all seven reference-frame slots and unconditionally uses each slot's stored value to index directly into that eight-entry table while comparing order hints to pick forward/backward skip-mode candidates, so any slot left unresolved by the missing derivation step is used as-is, and the lookup executes with the unresolved placeholder rather than a valid 0-7 index.
