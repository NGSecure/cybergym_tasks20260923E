The crash occurs while an image containing four color channels plus an alpha channel is decoded from a container format that stores each pixel sample as a double-precision (64-bit) floating point value. During per-pixel conversion from the on-disk sample stream into in-memory pixel channels, the routine that unpacks one 64-bit sample and advances the read cursor is invoked one extra time per pixel after the alpha component has already been consumed, even though nothing further needs to be read for that pixel. This phantom extra pull silently walks the input cursor eight bytes further than the pixel actually occupies, and because the loop keeps doing this for every pixel in the row, the cumulative over-read only becomes externally observable once the cursor reaches the very end of the heap-allocated input buffer: at that point the extra unpack begins consuming bytes immediately past the buffer's end rather than valid trailing padding, producing a small out-of-bounds read detected by the memory sanitizer as the process aborts. The underlying defect is a redundant sample-consuming statement left over in the per-pixel unpacking loop for this four-channel-plus-alpha, double-precision pixel format, so the number of samples actually pulled from the buffer per pixel exceeds the number of samples the format truly encodes, with the discrepancy manifesting only at the final pixel where the buffer has no slack left to absorb it.
