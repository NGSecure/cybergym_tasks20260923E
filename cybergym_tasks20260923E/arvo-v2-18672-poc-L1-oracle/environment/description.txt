GDAL's file-system oriented raster fuzz target opens an image whose trailing header is written in a keyword-value label format used by planetary-science imagery. The reader pulls a small fixed-size chunk of bytes from a designated position near the end of the file and scans it for a specific size-declaring keyword, recording both the numeric value that keyword announces and the byte offset at which the keyword's value text ends within that same small chunk. It then allocates a fresh buffer sized only to hold that announced value plus one byte, seeks back to the same position, and re-reads exactly that many bytes into the new buffer. To assemble the final label text, the code advances a pointer into this freshly allocated buffer by the previously recorded offset and treats whatever follows as a null-terminated string, appending it onto a growing text buffer. Nothing verifies that the announced size used to size the allocation is actually larger than the offset used to advance the pointer into it: when a crafted file declares a size that is smaller than, or equal to, that offset, the pointer starts beyond the end of the tiny allocation, and the routine that measures the resulting string's length by scanning forward for a terminating byte walks past the buffer's bounds, producing an out-of-bounds heap read. The fix adds a check that rejects the declared size whenever it does not exceed the recorded offset, before the buffer is ever allocated or the pointer arithmetic is performed.
