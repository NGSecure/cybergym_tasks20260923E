libheif's bundled HEVC decoder (libde265, fetched as a separate upstream dependency at build time rather than living in libheif's own source tree) crashes while parsing an HEVC slice NAL unit (ASan build): when the very first slice segment a decoder instance ever processes is a *dependent* slice segment rather than an independent one, the routine that inherits header fields from the previously-seen slice header still runs even though no independent slice header has ever been recorded yet for that decoder instance, because the pointer meant to reference that prior header is only ever tested against null but is never actually set to null when the decoder is created -- so it can hold arbitrary leftover memory instead of a real null. The field-inheriting copy then reads through that arbitrary, uninitialized pointer, producing a wild out-of-bounds memory read that crashes the process.
