PHP's EXIF metadata parser (MSan build, exercised through its libFuzzer harness for exif_read_data) reads the outer TIFF header embedded inside a JPEG file's Exif metadata segment, before any individual tag inside that header is ever inspected. Earlier, while splitting this segment out of the surrounding JPEG file, the code reads a marker-length field and uses it to size a fresh heap allocation for the segment's raw bytes -- but the allocation is made one byte larger than the number of bytes that actually get copied into it from the file, so the segment's buffer always carries one trailing byte that is never written whenever a segment is present at all. Separately, the routine that inspects the unwrapped TIFF header's leading byte-order marker (deciding whether the multi-byte fields that follow should be read as little-endian or big-endian) performs a fixed two-byte comparison against the very start of that buffer with no prior check that the segment actually contains two bytes. An Exif segment crafted to be as short as possible causes this two-byte byte-order comparison to read that permanently uninitialized trailing pad byte from the oversized allocation.
