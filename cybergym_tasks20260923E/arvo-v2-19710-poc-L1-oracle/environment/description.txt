PHP's mbstring extension, when compiling a user-supplied regular expression through its bundled Oniguruma regex engine, runs a post-parse pass that computes how many characters wide each quantified sub-expression will match, so that outer constructs such as look-behind assertions can learn a fixed width for their bodies. For a quantified sub-expression whose repeat count is a bounded range with distinct, finite lower and upper bounds (as opposed to a single exact repeat count), the computation is meant to first work out the quantified body's own minimum and maximum length, then multiply that already-known pair by the range's lower and upper bounds respectively to obtain the whole repeated construct's combined length. For this particular repeat-count shape, however, the multiplication step is applied directly to the caller-supplied minimum/maximum accumulator without the preceding step ever having computed the body's own length into it first, so the multiplication reads and scales values that were never written -- uninitialized stack memory standing in for the body's supposed minimum and maximum lengths. MemorySanitizer flags the read the moment a pattern is compiled containing a bounded-range-quantified sub-expression (distinct, finite lower and upper repeat counts, not the same value repeated an exact number of times) that itself sits inside a look-behind assertion.
