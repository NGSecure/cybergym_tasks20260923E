A bug in GDAL's GRIB2 driver's product-definition-section inventory parser makes AddressSanitizer report a 1-byte heap overflow read because the length check that gates the section buffer is sized only for the byte position one particular field needs, while a later block re-derives a template-dependent offset shift and uses it to read a following field (and a subsequent 4-byte time value) without re-validating the buffer length against that shifted position, so for the templates that apply the largest shift the parser reads past the end of the heap buffer allocated for the section.
