njs (nginScript, nginx's embedded JavaScript engine), ASan build: evaluating a script whose console.log() argument is built from a template-literal expression triggers the value-dump routine that renders that argument into a printable string. Internally this dump is built incrementally into a linked list of fixed-size memory chunks rather than one big buffer, and turning it into the final printable string requires a separate step that first adds up how many bytes are stored across all of those chunks and then asks the engine's shared allocator for one contiguous block of exactly that total size, before copying each chunk's bytes into it back-to-back. That running total is trusted as-is: nothing checks it for being a leftover error sentinel or an internal overflow before it is handed to the allocator as a size argument. When the total is bad in this way for the value being dumped, the allocator (which draws this new block from the very same small-object arena the chunks themselves were carved out of) hands back a block that does not actually have room for everything that still needs to be copied. The copy-out step, which walks the chunk list appending each chunk's bytes to the growing output pointer, keeps writing forward regardless, and before it finishes it runs into memory that one of the list's own not-yet-copied chunks is still occupying, so the destination write range starts overlapping the source chunk it is in the middle of reading from -- exactly the overlapping-ranges condition AddressSanitizer's memcpy interceptor flags as a memcpy-param-overlap violation.
