binutils' BFD library object-file reader for the VMS Alpha object format (ASan fuzz target over raw object-file bytes): a heap-buffer-overflow read happens while pulling a symbol-table entry out of a global-symbol-directory record parsed from the input file. Root cause: the symbol's name length is taken straight from one untrusted length byte stored inside that record (so it can be as large as 255) and used, without ever checking it against how many bytes are actually still left in the record's own already-allocated buffer, both to size the new symbol's heap allocation and to copy that many name bytes out of the record buffer -- so a record whose declared name length is bigger than the record's real remaining size makes the copy read past the end of the buffer it was parsed from.
