OpenThread's Thread mesh-networking stack (ASan build): a stack-buffer-overflow read happens while a router-capable node replies to an MLE Child Update Request sent by one of its attached children. When building that reply, the router echoes back the challenge value the child had just supplied, and decides how many bytes to copy out of a small, fixed-size buffer that holds the parsed challenge using the raw, attacker-supplied length field taken straight from the wire, rather than a length that has already been clamped to that buffer's real capacity. The validation applied to the incoming challenge only rejects lengths that are too short; it never rejects one that is too long, so a child can advertise a length a few bytes larger than the fixed buffer and still pass validation. When the router later copies that many bytes back out of the buffer to assemble its response, the read runs past the end of the buffer into adjacent memory on the stack.
